# LAN Danmaku · 局域网实时弹幕

一台电脑当**主机**，弹幕层悬浮在桌面最上方；局域网里的其它设备**两条路**参与：

1. **手机 / 任何电脑的浏览器**：打开主机给的地址就能发弹幕，零安装；
2. **其它电脑运行同一份软件选「加入弹幕」**：本机屏幕顶部同步滚动弹幕，
   桌面角落有一颗**桌宠**，点开就是一条紧凑输入条（含颜色），回车即发。

弹幕从右往左滚过屏幕顶部，不依赖外网、不经过任何服务器。

```
浏览器（零安装）──────────┐
                          ├──WebSocket──▶ 主机 App ──▶ 主机屏幕顶部弹幕层
其它电脑 App（加入模式）──┘            （HTTP + WS 服务）
```

## 两种运行模式

开发态（`npm start`）首次启动会弹出模式选择窗口，之后可从托盘菜单「切换模式」更改。
**正式发布的安装包**（见下方「打包成软件」）：主机版 / 加入版各自锁定模式、没有选择环节；
一体化版启动时选模式、运行中随时切换。

| | 主机模式 | 加入模式 |
|---|---|---|
| 弹幕层 | ✅ 本机屏幕顶部 | ✅ 本机屏幕顶部 |
| 提供 WS 服务 | ✅（要放行防火墙） | ❌ 只往外连，不动防火墙 |
| 控制台 | 地址/二维码/外观/屏蔽词等 | 连接主机 + 发言身份 + 外观 |
| 适合 | 活动组织者的电脑 | 局域网里其它想看+想发的电脑 |

加入模式也可以直接从命令行指定主机：`LAN-Danmaku.exe --join 192.168.1.23:7321`
（加入版安装包不用带参数，打开就是加入窗口）

## 快速开始

```bash
npm install
npm run icon      # 首次运行：生成图标资源
npm start         # 启动（弹出模式选择窗口）
npm run dev       # 启动并打开控制台 DevTools
```

启动后会出现两个东西：

- **控制台窗口**：显示访问地址和二维码、在线人数、弹幕外观设置、日志
- **弹幕层**：屏幕上边缘的一条透明带，覆盖在所有窗口之上，鼠标可以穿透点到桌面

把控制台里的地址（形如 `http://192.168.1.23:7321`）发给同网段的人，用浏览器打开就能发弹幕。

## 发言：桌面角落的桌宠

加入模式下桌面上会出现一颗小球，那就是发送入口 —— 不占地方，用完自己收回去：

| 操作 | 效果 |
|---|---|
| 点一下球 | 展开成一条紧凑输入条：打字 → **回车即发**，发完自动收回 |
| 按住拖动 | 挪到顺手的位置，位置会记住 |
| 色点 | 输入条左下角一排颜色，点一下即选，下次沿用 |
| 身份标签 | 点它改昵称 / 切匿名 |
| 右键球 | 面板展开时收起面板，收起时隐藏小球（托盘菜单可再调出来） |
| 托盘菜单 | 「显示桌宠 / 隐藏桌宠」，主机模式也有 |

**昵称在打开输入条之前就定好**：第一次点开时会先让你设一次身份 —— 起个名字，或者直接勾
「匿名发送」（弹幕上只会显示"匿名"）。设过之后每次发言直接用，不再重复问。
加入窗口里也有同一份「发言身份」设置，两边改的是同一个值。

颜色、昵称、身份都会落盘，重启后还在。桌宠发的弹幕和网页端发的一样，
要过主机的长度校验、屏蔽词和限流（本机发送不享受任何特权）。

## 网线局域网的关键注意事项

1. **必须是同一网段。** 发送端 IP 和主机 IP 的前三段要一致（`192.168.1.x` 对 `192.168.1.x`）。
   控制台会显示主机当前网段，对不上就连不上。
2. **一台机器插了网线又开了 WiFi 时**，控制台会出现"网卡"下拉框，选有线那块。
   默认已经优先挑有线网卡了。
3. **防火墙。** 这是这类工具最常见的坑：服务在跑、二维码也出来了，但别人死活连不上。
   控制台启动后会自动做一次自检，失败会直接挂警告条并给出一键跳转。
   手动处理：`Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙`，把程序在「专用网络」下勾上。
4. **交换机不要开端口隔离。** 部分企业级交换机会隔离端口，导致互相 ping 不通。

## 公网服务器模式（跨网络弹幕）

局域网玩不过瘾？把服务端单独丢到一台有公网 IP 的机器（VPS / 云服务器）上，
全世界的人都能发弹幕、桌面客户端也能跨网络同步观看 —— 不依赖任何第三方服务。

```bash
# 服务器上（需 Node ≥ 18，把整个项目传上去即可）
npm install --omit=dev
npm run serve
```

启动后打印三个入口：

| 入口 | 地址 | 说明 |
|---|---|---|
| 发送页 | `http://<域名/IP>:7321/` | 任何浏览器打开就能发，手机同样适用 |
| 管理台 | `http://<域名/IP>:7321/admin/` | 管理口令登录 |
| 客户端 | 加入模式填服务器地址 | 桌面弹幕层 + 桌宠发言，支持 https/wss 域名 |

**管理台能做什么**：发固定公告（上/中/下落点 + 停留时长）、清空全端弹幕、
暂停/恢复上屏、在线改屏蔽词、**一键开公网隧道**。管理口令首次启动自动生成（打印在控制台，
也写在配置文件里），配置文件路径由 `LAN_DANMAKU_SERVER_CONFIG` 指定，
默认在 `~/.lan-danmaku-server/config.json`。

**一键开公网（内网穿透）**：服务器没在公网机器上、也没做端口映射时，
管理台里点"一键开启公网"即可 —— 服务端会自动调用 `cloudflared` 建立
Cloudflare 快速隧道（免费、免注册），并把分配的 `https://xxx.trycloudflare.com`
地址显示在管理台上，复制发出去就能用。说明：

- 服务器会按顺序自动找 `cloudflared`：配置文件 `cloudflaredPath` > 环境变量
  `LAN_DANMAKU_CLOUDFLARED` > 服务器程序目录 > 系统 PATH > 系统临时目录；
  找不到时管理台会提示下载（[cloudflared releases](https://github.com/cloudflare/cloudflared/releases)）。
- 隧道接口走 `/api/tunnel`（查询/开启/关闭），本机调用免鉴权，远程调用必须带
  `x-admin-token`（管理台会自动带上）。
- 快速隧道的地址是随机的，隧道重开就换；想固定域名需要 Cloudflare 账号 + 自己的域名。

**公网安全边界**（与局域网模式的核心区别）：

- **房间口令 `roomToken`**：配置里设了它，发言必须带对口令（观看不受限）。
  公网裸奔必设；客户端侧发送页和加入模式都有口令输入框，填一次本地记住。
- **管理口令 `adminToken`**：管理台登录凭证，认证失败有日志。
- 文本长度、控制字符清洗、颜色白名单、按 IP 限流全部在服务端做，与局域网共用同一份实现。
- 建议前面挂 Nginx/Caddy 上 HTTPS：客户端会自动切 `wss`，代码零改动。

**客户端怎么连**：加入模式窗口的地址栏填公网域名或 IP（如 `danmaku.example.com:7321`），
口令栏按需填。局域网自动发现不受影响，两者可以并存使用。

测试：`node scripts/smoke-public.js`（口令、管理员、白名单等公网专属逻辑的冒烟测试）。

## 打包成软件（两个版本）

为了"发给别人装完就能用、不会误操作"，打包分成两个**互相独立**的安装包，各自把运行模式锁死：

| | 主机版 | 加入版 |
|---|---|---|
| 安装包 | `LAN-Danmaku-Host-<版本>-Setup.exe` | `LAN-Danmaku-Join-<版本>-Setup.exe` |
| 免安装版 | `LAN-Danmaku-Host-<版本>-Portable.exe` | `LAN-Danmaku-Join-<版本>-Portable.exe` |
| 启动后 | 直接开服务 + 控制台 + 弹幕层 | 直接进"加入弹幕"窗口，填主机地址 |
| 能否切换模式 | ❌ 托盘里没有「切换模式」 | ❌ 同上 |
| 配置目录 | `%APPDATA%\LAN Danmaku Host` | `%APPDATA%\LAN Danmaku Join` |

两个包可以装在同一台机器上互不干扰（appId、程序名、配置目录都不同）。

```bash
npm run dist:host    # 只打主机版 → dist/host/
npm run dist:join    # 只打加入版 → dist/join/
npm run dist:all     # 只打一体化版（启动可选模式）→ dist/all/
npm run dist:win     # 主机版 + 加入版都打
npm run dist:dir     # 只产出解包目录，用于快速验证

# 产物自检（不启动 GUI，直接读 app.asar 确认模式锁生效）
node scripts/verify-package.js dist/host host
node scripts/verify-package.js dist/join join
```

装到目标机器后双击运行即可，不需要装 Node。加入版的用法：把主机控制台里的地址
（形如 `192.168.1.23:7321`）填进加入窗口，点连接，本机屏幕顶部就开始同步滚动弹幕。

**锁死模式是怎么做的**：单模式版用 `build/host.yml` / `build/join.yml` 的
electron-builder `extraMetadata` 把 `appMode` 写进打包后的 `package.json`，
主进程启动时读它并锁定模式（托盘里连「切换模式」都不出现）。一体化版 `build/all.yml`
不带该字段，启动时弹模式选择窗口、运行中可随时切换。开发态（`npm start`）读不到该字段，
因此保留"启动时选模式"的行为。

## 设计要点

**发送端为什么是网页而不是客户端**
零安装、跨 iOS/Android/Windows/Mac，成本全压在主机端一次开发上。局域网场景下这个取舍收益极高。

**弹幕渲染为什么用 Web Animations API**
`transform` 动画跑在合成线程，主线程卡顿也不掉帧；可随时 `cancel` / 精确读进度；
节点池复用不会残留 `fill: forwards` 的效果。轨道调度只需保证新弹幕入场时上一条的右边缘
已经离开屏幕右边缘，同轨道速度一致就永远不会追尾。

**桌宠为什么是「一个窗口两个尺寸」**
收起 64×64、展开 460×152，是同一个无边框透明窗口靠 `setBounds` 换尺寸，不是两个窗口。
展开时窗口的**右边界和上边界往外撑**，小球在 DOM 里固定在面板右下角，
于是球在屏幕上的位置视觉上纹丝不动，"点球 → 长出输入条"才连贯。
拖动没有用 `-webkit-app-region: drag`（那个会吞掉点击事件，点不开了），
而是自己判位移：小于 4px 算点击、大于算拖动，松手才把位置写进配置。

**文字宽度必须实测**
宽度用 `canvas.measureText` 预测量，绝不用字符数估算——中英文和 emoji 混排下估算误差
会直接导致轨道判断失准、弹幕糊成一团。

**客户端传来的数据一律不可信**
文本长度上限、控制字符清洗、颜色 hex 白名单、字号 clamp、单条消息字节上限、
按 IP 限流，全部在服务端做。静态资源只放行 `sender/` 和 `shared/` 两个目录，并做了目录穿越防护。

## 已知限制

- 独占全屏的应用（全屏游戏、部分播放器）之上无法覆盖，需改用无边框窗口模式
- 单房间模式，协议层已预留 `room` 字段，多房间不用改协议
- 暂不支持 macOS 打包（代码里已处理 `setVisibleOnAllWorkspaces`，但未验证）

## 渲染兼容性说明

主进程默认做了两个兜底（`src/main/main.js` 顶部）：

- **禁用硬件加速 + `in-process-gpu`** —— 远程桌面、无 GPU 的服务会话、部分虚拟机上，
  Chromium 的 GPU 进程起不来会直接 `FATAL: GPU process isn't usable. Goodbye.` 闪退。
  弹幕只是几行文字的 transform 动画，软件渲染绰绰有余。
- **`no-sandbox`** —— 部分受限环境的沙箱化渲染子进程会被系统直接杀掉，导致渲染层反复崩溃。
  本应用两个渲染器只加载本地文件（contextIsolation 开、nodeIntegration 关、
  对外网页跑在用户自己的浏览器里），关沙箱的实际安全代价很小。

想改回 Chromium 默认行为：`LAN_DANMAKU_GPU=1` 恢复 GPU 加速，`LAN_DANMAKU_SANDBOX=1` 恢复沙箱。
真机（有正常桌面和 GPU）上开启 GPU 加速动画会更省 CPU，可自行实测切换。
